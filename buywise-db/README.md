# buywise-db

Every script that creates or fills a database, and the seed data it loads, lives here - one folder per database (ADR-046).
services: `01-ddl/` = structure (schemas, tables, rules; Flyway), `02-dml/` = SQL that inserts the seed data, `03-data/` = that data (JSON, generated by `buywise-data/tools`, `make data`). `database/` and `agent/` hold their files directly (one script each, no seed data).
Keycloak and LiteLLM create their own tables in their own databases; nothing for them here.
Design (databases, data model, backups, PII): [buywise-docs/06-buywise-db/01-design.md](../buywise-docs/06-buywise-db/01-design.md).

## Layout
| Folder | Database | What | Runs how |
|---|---|---|---|
| `database/01-databases.sh` | all | Creates the 4 databases (`services`, `agent`, `keycloak`, `litellm`), one user each, `REVOKE ... FROM PUBLIC`, pgvector in `agent` | Automatically, once, on the first Postgres start (compose mounts this folder) |
| `services/01-ddl/` | `services` | Schemas and tables: V1 catalog, V2 inventory, V3 availability rule, V4 customers + orders | `make migrate` (Flyway container) and on buywise-services start (Gradle packs them into the app) |
| `services/02-dml/` | `services` | 01 catalog, stores, stock; 02 customers, orders, sales tax | `make seed` (replaces existing seed rows) |
| `services/03-data/` | `services` | The JSON those scripts load: `catalog/*.json`, stores, stock, customers, orders, sales tax; `staff.json` + `tickets.json` wait for their tables | Copied into the container at `/tmp/seed` by `make seed` (Postgres reads only its own files) |
| `agent/` | `agent` | V1 `rag.chunks` + HNSW vector index | `make migrate` (Flyway container `flyway-agent`) |

## Run order on a fresh machine
```bash
make up        # 1. Postgres starts; database/01-databases.sh runs (first start only)
make migrate   # 2. tables in services and agent
make seed      # 3. seed data in services
make ingest    # 4. knowledge chunks in agent (buywise-agent reads docs, writes rag.chunks)
```
`make flyway-info` shows what is applied in both databases.

## Rules
- **Never edit an applied migration** - not even a comment: Flyway checks each file's checksum. A change is a new file (`V5__...sql`).
  Old comments inside applied files may name earlier folders (e.g. `cluster/` in agent V1) - left as is on purpose.
- Migration names: `V<number>__<description>.sql` (two underscores).
- No foreign keys or joins across schemas (ADR-010).
- Seed scripts are not migrations: they may change, and they `TRUNCATE` first (one transaction, all or nothing).
